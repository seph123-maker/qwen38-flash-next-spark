## What changes (7 lines, everything else byte-identical)

| # | Setting | Before (live 2026-10-14) | After (proposed) | Why |
|---|---------|--------------------------|------------------|-----|
| 1 | `--kv-cache-dtype` | `auto` → bf16 KV | `fp8_e4m3` | Halves full-attention KV from 24.0 to 12.0 KiB/token → paged pool grows 539,393 → ~1.17M tokens. In-kernel-dequant path verified in this build's source: `qwen4_exp/nvidia/qsa.py` lists `fp8_e4m3` in `supported_kv_cache_dtypes` and dequantizes inside the QSA Triton kernel; the QSA indexer side-cache stays bf16 regardless, so block-ranking is bit-identical. Only exposed error: one-shot K/V write rounding. |
| 2 | `--max-num-seqs` | `8` | `4` | Single-user box; 6 idle slots hold ~0.278 GiB/slot of fixed GDN state. Reclaim ~1.1 GiB into the paged pool. |
| 3 | `--max-model-len` | `500000` | `524288` | Exact 2× power-of-two ratio for the YaRN fix below. |
| 4 | YaRN `factor` (hf-overrides) | `4.0` | `2.0` | Recipe carry-over error: factor 4.0 calibrates positional stretch for 1,048,576 tokens (4× the 262,144 native window) while we cap at 500K — over-interpolating rotary phase ~2× for our whole working range. HF convention: factor = target/native. |
| 5 | `--speculative-config` | `max_model_len:500000` | `max_model_len:524288` | Keep draft head aligned with #3. `num_speculative_tokens` stays 2 (measured acceptance pos0 71.7% / pos1 53.9% → 2.26 tok/pass; n=3 parked for Phase C). |
| 6 | `VLLM_PLE_MMAP_FAST_ROWS` | `0` | `512` | Code default restored. Semantics (this build): batch size ≤ fast_rows runs the PLE gather inline on the calling thread; 0 disables the fast path for every lookup. Single-stream MTP decode looks up ~384 rows/pass — strictly inline territory. Gate 1 A/Bs 512 vs 256 fallback. |
| 7 | `VLLM_PLE_MMAP_WORKERS` | `32` | `16` | GB10 has 20 CPU cores; 32 gather threads oversubscribe the decode loop. Only exercised when #6 dispatches (prefill, >512-row batches). |

**Unchanged:** model checkpoint (NVIDIA NVFP4 `-fp8hybrid`), GMU `0.80`,
chunked prefill `8192`, prefix caching, `PIECEWISE` graphs + 19-entry
`splitting_ops`, `VLLM_QSA_DET_TOPK=1`, draft vocab `/opt/llm/draft_vocab_65536.npy`,
`MADVISE=random`, `PREWARM=0`, deep-gemm off, flashinfer autotune off (Phase C),
5080 image lane (stays bf16).

## Expected after-state
- GPU KV cache ≥ 1.05M tokens (abort below 1.01M), single-session 524,288 at 2.0× pool concurrency
- swap 0, MemAvailable ≥ 14 GiB idle, decode ≥ 95% of the 43.6 tok/s baseline
- NLL on a 32,776-token real agent trace: baseline 2.999 nats/token; pass = Δ ≤ +0.010

## Validation gates (post-restart, `gates/run_gates.py`)
1. **PLE gather** — `gather ms/op` < 4.1 with inline path active; > 4.7 → set FAST_ROWS=256.
2. **Capacity/swap** — thresholds above; abort → rollback.
3. **Fidelity** — 3A NLL on gold trace ≤ +0.010; 3B exact 64-hex SHA-256 reconstruction of checkpoints at ≥120K context.
4. **Cache correctness** — cold-vs-warm replay of an identical token array (MTP decode forced across block boundaries first); divergence → disable prefix caching, keep everything else.

## Provenance & honesty notes
- Derived from a review round with an external frontier model (referred to here as "Argon"). Its draft contained three would-have-broken-boot errors (relative draft-vocab path, a self-referencing env placeholder, a dev-mode-only reset endpoint) corrected by source inspection before anything here was staged. Every load-bearing claim was independently re-measured or recomputed; where it conflicted with our live data (e.g. KV bytes/token), the measured value won — including a correction to *our own* earlier figure (bf16 KV is 24.0 KiB/token; the widely-quoted 12 KiB omits the K+V factor).
- fp8 KV at extended (YaRN) context on this QSA hybrid is, to our knowledge, not published anywhere else; the enabling fact is build-specific (NVIDIA path supports it; the AMD path in the same tree raises). Do not generalize this doc to other forks.
- YaRN factor/length pairing follows the HF transformers convention and the YaRN paper (2309.00071); nothing else in this table is speculative.
